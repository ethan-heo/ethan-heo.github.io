# 글 목록과 상세(POST) — 도메인 특화 가이드

## 외부 의존성

해당 없음. 이 도메인만 독점적으로 쓰는 외부 패키지가 없다. 브라우저 API와 내부 모듈에만 기댄다.

| 대상 | 종류 | 용도 |
| --- | --- | --- |
| `IntersectionObserver` | 브라우저 API | 감시 요소가 화면에 들어오는 시점을 잡는다 |
| `Intl.DateTimeFormat` | 브라우저·런타임 API | 목록은 `2026.08.27`, 머리말은 `2026년 8월 27일` |
| `astro:content`의 `render` | 프레임워크 모듈 | 본문 HTML과 `headings`를 얻는다 |
| `src/lib/posts.ts` | 내부 모듈 | `getVisiblePosts`, `toSearchEntries`, `getRelatedPost`, `getReadingMinutes`, `toSlugPath`, `toPostUrl` |

### 설정

| 항목 | 값의 출처 | 비고 |
| --- | --- | --- |
| `INITIAL_VISIBLE` | `src/pages/posts/index.astro`의 스크립트 | 20 |
| `VISIBLE_STEP` | 같은 곳 | 10 |
| `SENTINEL_MARGIN` | 같은 곳 | `0px 0px 200px 0px` |
| 본문 폭 | `[...slug].astro`의 `max-w-[680px]` | 이미지 폭 상한 1360px의 근거 |
| 본문 밀도 | `Prose.astro` | 1rem, 줄 간격 1.45 |

## 핵심 테스트 시나리오

| ID | 상황 | 기대 동작 |
| --- | --- | --- |
| T1 | 검색 색인을 확인한다 | 제목·요약·태그만 들어가고 다른 필드는 없다 |
| T2 | 검색어를 입력하고 제출 전후를 본다 | 입력 중에는 목록이 그대로이고 제출 시점에만 바뀐다 |
| T3 | 결과가 0편인 검색어를 낸다 | 목록이 감춰지고 결과 없음 안내가 나오며 감시 요소도 감춰진다 |
| T4 | 정렬을 바꾼다 | 순서가 뒤집히고 보이는 화살표가 하나로 유지된다 |
| T5 | 글을 20편 넘게 두고 연다 | 앞에서부터 20편만 드러난다 |
| T6 | 목록 끝까지 스크롤한다 | 노출 수가 10 늘고, 남은 글이 없으면 감시 요소가 숨는다 |
| T7 | 검색어 제출과 정렬 전환 뒤 노출 수를 본다 | 다시 20편으로 돌아간다 |
| T8 | 글 수를 2편, 9편, 10편으로 바꾼다 | 각각 `총 2편`, `총 9편`, `총 10편`으로 나온다 |
| T9 | 발행한 글을 0편으로 둔다 | `ul` 대신 `EmptyState`가 나온다 |
| T10 | 상세 화면의 마크업을 본다 | 돌아가기 링크가 없고 머리말이 `article`의 첫 요소다 |
| T11 | 상세 화면의 가로선을 본다 | 목차 아래 한 줄만 있고 날짜 줄 위에는 없다 |
| T12 | 목차 목록의 계산값을 본다 | `list-style-type`이 `none`이고 왼쪽 안쪽 여백이 20px다 |
| T13 | 본문 문단의 계산값을 본다 | 글자 크기 16px, 줄 간격 23.2px |
| T14 | 소제목이 없는 글과 `h3`만 있는 글을 연다 | 각각 목차를 그리지 않고, 한 단계로 나열한다 |
| T15 | `related`를 비운 글을 연다 | 이어 볼 글 영역과 그 위 구분선이 함께 사라진다 |
| T16 | `category`가 있는 글과 없는 글의 눈썹 줄을 본다 | 있으면 `분류 · N분 읽기`, 없으면 `N분 읽기` |
| T17 | 키보드로 목록과 상세를 순회한다 | 조작의 접근 가능한 이름이 목적지나 동작을 설명하고 포커스 표시가 보인다 |
| T18 | 표와 코드 블록이 있는 글을 좁은 화면에서 연다 | 각자의 컨테이너 안에서만 가로로 스크롤한다 |

### 실행 방법

## 트러블슈팅

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 검색과 정렬 조작이 보이지 않는다 | 스크립트가 아직 붙지 않았거나 오류로 멈췄다 | 콘솔을 확인한다. 조작은 동작하는 시점에만 드러내는 것이 규칙이다 |
| 검색해도 목록이 그대로다 | 입력만 하고 제출하지 않았다 | 제출 시점에만 실행하는 규칙이다 |
| 특정 글이 검색에 걸리지 않는다 | 본문은 색인하지 않는다 | 제목·요약·태그에 해당 낱말이 있는지 확인한다 |
| 스크롤해도 글이 늘지 않는다 | 감시 요소가 감춰져 있거나 관찰 대상에서 빠졌다 | 남은 글이 있는지, `scroll-sentinel`의 `hidden` 상태가 어떤지 확인한다 |
| 항목 순서가 검색 결과와 다르다 | 다시 그릴 때 순서를 옮기지 않았다 | 고른 결과의 순서대로 `list.append`로 옮겨 붙이는지 확인한다 |
| 화살표 두 개가 동시에 보인다 | 정렬 상태에 따른 `hidden` 전환이 한쪽만 걸렸다 | 두 아이콘의 `toggleAttribute`가 반대 조건으로 짝을 이루는지 확인한다 |
| 목차에 소제목이 빠진다 | 앵커 대상이 `h2`와 `h3`뿐이다 | 더 깊은 단계는 목차에 넣지 않는 규칙이다 |
| 목차 항목이 한 단계로만 나온다 | 앞선 `h2` 없이 `h3`가 먼저 나왔다 | 갈 자리가 없어 바깥 목록에 두는 정상 동작이다. 본문의 소제목 순서를 확인한다 |
| 이어 볼 글이 나오지 않는다 | `related`가 없거나 초안을 가리킨다 | 대상 글의 `draft` 값을 확인한다. 없는 글을 가리키면 빌드가 먼저 멈춘다 |
| 본문이 다른 화면보다 촘촘하지 않다 | 전역 토큰을 바꿨다 | 밀도는 `.prose` 안에서만 조정한다. 전역 토큰을 바꾸면 다른 화면까지 작아진다 |
