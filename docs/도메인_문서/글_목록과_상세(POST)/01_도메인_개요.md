# 글 목록과 상세(POST) — 도메인 개요

계획서 출처: `docs/plans/2026-08-28-all-posts-screen/archive/`, `docs/plans/2026-08-28-all-posts-refinement/archive/`, `docs/plans/2026-08-28-archive-infinite-scroll/archive/`, `docs/plans/2026-08-28-post-detail-screen/post/`, `docs/plans/2026-08-28-post-detail-refinement/post/`

## 도메인 정의

이 도메인은 글을 찾아 들어가서 읽고 나오는 흐름을 맡는다. `/posts`의 전체 목록과 그 위의 검색·정렬·무한 스크롤, 그리고 `/posts/<post.id>`의 본문 화면과 머리말·목차·이어 볼 글이 여기에 속한다.

글을 고르고 정렬 기준을 만들어 주는 일은 [`콘텐츠(CONTENT)`](../콘텐츠(CONTENT)/01_도메인_개요.md)가, 본문 HTML의 변환과 조판은 [`본문_렌더링(RENDER)`](../본문_렌더링(RENDER)/01_도메인_개요.md)가 맡는다.

### 책임 범위

| 구분 | 내용 |
| --- | --- |
| 담당한다 | `/posts`와 `/posts/<post.id>` 두 경로, 검색 실행과 결과 표시, 정렬 전환, 노출 개수 관리와 감시 요소, 글 카드 표현, 글 머리말, 목차 계층 구성, 이어 볼 글 영역 |
| 담당하지 않는다 | 글 선별·검색 색인 문자열 생성·주소 계산(CONTENT), 마크다운 변환과 소제목 `id` 부여(RENDER), 헤더·푸터·토큰(DESIGN) |

## 유비쿼터스 용어 사전

| 용어 | 영문 표기 | 정의 |
| --- | --- | --- |
| 모든 글 화면 | `/posts` | 발행한 글 전체를 한자리에 두는 화면. 눈썹 문구는 `Archive`다 |
| 글 카드 | `PostCard` | 목록의 항목 하나. 제목, 요약, 태그, 날짜를 담는다 |
| 검색 | `PostSearch` | 제목·요약·태그를 대상으로 목록을 좁히는 조작. 제출 시점에만 동작한다 |
| 정렬 토글 | `SortToggle` | 최신순과 오래된 순을 오가는 버튼. 보이는 화살표가 현재 정렬을 알린다 |
| 노출 개수 | `state.visible` | 목록에서 실제로 드러낸 글 수 |
| 감시 요소 | `scroll-sentinel` | 목록 끝에 두고 화면에 들어오면 다음 묶음을 드러내는 요소 |
| 글 상세 화면 | `/posts/<post.id>` | 글 한 편의 본문 화면 |
| 글 머리말 | `PostHeader` | 분류와 읽기 시간, 제목, 요약, 날짜, 태그를 담는 영역 |
| 목차 | `PostToc` | 본문 소제목을 두 단계로 나열하는 영역. 제목은 「이 글의 구성」이다 |
| 이어 볼 글 | `RelatedPost` | 본문 아래의 다음 글 링크. 눈썹 문구는 「다음으로 읽기」다 |

## 핵심 비즈니스 규칙

1. 목록의 모든 글은 빌드 시점에 마크업으로 내보내고, 검색과 정렬과 무한 스크롤은 그 마크업을 감추고 드러내는 방식으로 동작한다. 화면의 글자가 아니라 미리 만든 검색 항목으로 판정한다.
2. 검색은 제출 시점에만 실행한다. 입력하는 동안에는 목록이 그대로다.
3. 검색 대상은 제목·요약·태그를 소문자로 합친 문자열이고, 입력값도 공백을 떼고 소문자로 낮춰 부분 일치로 판정한다.
4. 정렬은 발행일 내림차순이 기본이고, 토글하면 그 결과를 뒤집는다. 화살표는 최신순이면 아래, 오래된 순이면 위를 가리키며 보이는 아이콘은 언제나 하나다.
5. 처음 드러내는 글은 20편이고, 감시 요소가 화면에 들어올 때마다 10편씩 늘린다. 목록 끝이 보이기 전에 붙이도록 200px의 여유를 둔다.
6. 검색어를 제출하거나 정렬을 바꾸면 노출 개수를 20편으로 되돌린다.
7. 더 드러낼 글이 남아 있을 때만 감시 요소를 관찰 대상으로 둔다.
8. 결과 요약은 `총 N편` 형태이며 검색 결과에 따라 갱신된다.
9. 검색과 정렬 조작은 스크립트가 붙기 전까지 감춘다. 눌러도 반응하지 않는 조작을 보이지 않기 위해서다.
10. 글 상세의 첫 요소는 글 머리말이다. 헤더 아이콘과 겹치는 돌아가기 링크는 두지 않는다.
11. 가로선은 목차 아래 한 줄만 남긴다. 날짜 줄과 목차를 겹겹이 두르지 않는다.
12. 목차는 번호 없이 들여쓰기로 계층을 보인다. `h3`는 바로 앞 `h2`의 하위로 들어간다.
13. 본문은 1rem 크기와 1.45 줄 간격을 쓴다. 전역 토큰이 아니라 `.prose` 안에서만 이 밀도를 적용한다.
14. 이어 볼 글이 없으면 영역과 그 위 구분선이 함께 사라진다.

### 예외 케이스

| 상황 | 처리 |
| --- | --- |
| 발행한 글이 없다 | 목록 대신 「아직 발행한 글이 없습니다.」 안내를 그린다 |
| 검색 결과가 0편이다 | 목록 영역을 감추고 「검색 결과가 없습니다.」를 보이며 감시 요소도 감춘다 |
| 자바스크립트가 없다 | 검색과 정렬 조작이 나타나지 않고 전체 목록이 그대로 보인다 |
| 글이 20편 이하다 | 처음부터 전부 드러나고 감시 요소가 감춰진다 |
| 소제목이 하나도 없다 | 목차를 그리지 않는다 |
| 앞선 `h2` 없이 `h3`가 먼저 나온다 | 갈 자리가 없으므로 바깥 목록에 그대로 둔다 |
| `related`가 없거나 초안을 가리킨다 | 이어 볼 글 영역이 사라진다 |
| `category`가 없는 글이다 | 머리말 눈썹 줄에 읽기 시간만 남긴다 |
