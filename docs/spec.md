# 블로그 제품·콘텐츠 명세

`DESIGN.md`의 시각·컴포넌트 기준을 실제 블로그 기능과 콘텐츠 운영에 연결하는 문서다.

## 제품 방향

- 검색이나 공유 링크로 처음 방문한 독자가 글의 주제와 최신성을 빠르게 파악한다.
- 정적 HTML을 우선 제공하고, Markdown 콘텐츠를 검증된 페이지로 발행한다.
- 현재 콘텐츠 필드는 `title`, `date`, `summary`, `tags`, `draft`다.

## 콘텐츠 모델 확장 초안

| 필드 | 용도 | 필수 여부 |
|---|---|---|
| `slug` | 제목 변경과 URL을 분리 | 권장 |
| `author` | 작성자 정보와 구조화 데이터 | 여러 작성자가 있을 때 필수 |
| `updatedAt` | 수정일과 최신성 표시 | 수정한 글에 필수 |
| `coverImage` / `imageAlt` | 공유 카드와 대표 이미지 | 이미지 사용 시 필수 |
| `canonicalUrl` | 외부 원문이나 중복 콘텐츠 표시 | 해당할 때만 |
| `series` | 연재 글 그룹화 | 연재 글에만 |
| `relatedPosts` | 관련 글 연결 | 관련 글 기능 도입 시 |

값이 없는 필드는 빈 문구나 임의의 기본값으로 채우지 않는다.

## 탐색 및 읽기 기능

- 태그별 목록과 공유 가능한 태그 URL을 제공한다.
- 글 수가 늘어나면 제목·요약·본문 검색과 일치 문맥을 제공한다.
- 글 상세에는 `h2`, `h3`에서 자동 생성한 목차를 제공한다.
- 글 하단에 이전 글·다음 글 또는 관련 글을 제공한다.
- 코드 블록에는 복사 버튼과 `aria-live` 성공 안내를 제공한다.

## 운영 상태 및 오류 화면

- 404, 검색 결과 없음, 발행 글 없음 상태를 별도로 설계한다.
- 오래된 글에는 수정일 또는 기준일 안내를 표시한다.
- 외부 콘텐츠가 실패해도 본문 전체를 막지 않고 해당 위치에 대체 문구를 표시한다.
- 초안은 프로덕션 목록·사이트맵에서 제외하고 필요한 경우 `noindex`를 적용한다.

## SEO·GEO 구현 계약

- 페이지 제목은 `[글 제목] | [사이트 이름]` 형식을 기본으로 한다.
- 설명은 `summary`를 사용하고 핵심 대상·결론·범위를 1~2문장으로 작성한다.
- 글 상세 JSON-LD에는 제목, 요약, URL, 발행일, 수정일, 작성자, 사이트 이름을 일관되게 매핑한다.
- canonical은 빌드 시 정규 경로를 생성하며, `canonicalUrl`은 외부 원문이 있을 때만 사용한다.
- `<html lang="ko">`, Open Graph, sitemap, RSS 또는 Atom 피드를 제공한다.
- 대표 이미지에는 대체 텍스트, 고정 크기, 공유 카드용 비율을 정의한다.
- 첫 1~2문장에 핵심 답변을 제시하고, 한 문단에 하나의 주장과 근거를 둔다.
- 날짜, 버전, 범위, 출처를 명시해 AI가 내용을 정확히 해석하고 인용할 수 있게 한다.

## 성능 기준

- 정적 HTML을 우선 제공하고 상호작용에 필요한 JavaScript만 포함한다.
- 이미지는 AVIF 또는 WebP와 반응형 크기를 우선한다.
- 본문 이미지는 지연 로딩하고 첫 화면 이미지는 우선 로딩을 검토한다.
- 웹 폰트를 추가할 때 표시 지연과 레이아웃 이동을 확인한다.
- 배포 전 Lighthouse에서 성능·접근성·SEO를 점검한다.

## 구현 순서

1. `BaseLayout`에 메타 태그, canonical, Open Graph, 테마 토큰을 연결한다.
2. `PostHeader`, `Prose`, `ThemeToggle`, 404 화면을 구현한다.
3. `slug`, `updatedAt`, `author`를 콘텐츠 모델과 JSON-LD에 연결한다.
4. 태그 탐색, 검색, 목차, 관련 글을 단계적으로 추가한다.
5. sitemap·RSS, 이미지 최적화, Lighthouse 점검을 배포 과정에 포함한다.
