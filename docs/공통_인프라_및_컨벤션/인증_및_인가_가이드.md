# 인증 및 인가 가이드

## 인증 방식

해당 없음. 이 프로젝트에는 로그인이 없다. 사용자를 식별하지 않고, 계정이나 세션을 만들지 않으며, 서버 런타임 자체가 없다. 모든 방문자가 같은 정적 파일을 받는다.

| 항목 | 내용 |
| --- | --- |
| 방식 | 없음 |
| 발급 경로 | 없음 |
| 유효 기간 | 없음 |
| 갱신 방법 | 없음 |

### 토큰 구조

해당 없음. 토큰을 발급하지 않는다. 브라우저에 남는 유일한 값은 개인을 식별하지 않는 테마 선택이며, 그 규약은 [`디자인_시스템(DESIGN)`](../도메인_문서/디자인_시스템(DESIGN)/02_도메인_모델.md)에 있다.

| 키 | 저장소 | 값 | 개인 식별 |
| --- | --- | --- | --- |
| `theme` | `localStorage` | `light` 또는 `dark` | 하지 않는다 |

## 인가 규칙

해당 없음. 역할을 두지 않는다. 대신 글의 공개 여부를 가르는 규칙 하나가 그 자리를 대신한다.

| 구분 | 볼 수 있는 것 |
| --- | --- |
| 방문자 | 운영 빌드에 포함된 모든 글 |
| 작성자(로컬 개발 서버) | 초안을 포함한 모든 글 |

작성자와 방문자를 가르는 것은 신원이 아니라 실행 환경이다. `draft: true`인 글은 `import.meta.env.PROD`가 참일 때 목록과 정적 경로에서 모두 빠지므로, 운영 산출물에는 그 글의 파일 자체가 존재하지 않는다. 감춰 둔 페이지를 주소로 찾아 들어갈 여지를 남기지 않는다.

### 엔드포인트 보호

보호가 필요한 경로가 없다. 세 경로 모두 인증 없이 열린다.

| 경로 패턴 | 요구 조건 |
| --- | --- |
| `/` | 인증 불필요 |
| `/posts` | 인증 불필요 |
| `/posts/<post.id>` | 인증 불필요. 단, 운영 빌드에서는 노출 대상 글의 경로만 생성한다 |

## 실패 처리

인증 실패라는 개념이 없으므로 상태 코드로 응답하는 자리도 없다. 접근과 관련해 실제로 일어나는 상황은 다음 세 가지다.

| 상황 | 결과 | 처리 |
| --- | --- | --- |
| 초안 글의 주소로 직접 들어온다 | 정적 호스팅의 404 | 그 경로를 아예 만들지 않았기 때문이다. 애플리케이션이 따로 응답하지 않는다 |
| 지운 글의 주소로 들어온다 | 정적 호스팅의 404 | 위와 같다 |
| `localStorage` 접근이 막혔다 | 조용히 넘어간다 | 시스템 테마를 따르고 이 세션 안에서만 전환을 유지한다 |

404 페이지의 문구와 형태는 정적 호스팅의 기본 동작을 따른다. 메시지 작성 규칙은 [`공통_에러_코드.md`](공통_에러_코드.md)와 일치시킨다.
