# 공통 에러 코드

## 에러 응답 형식

해당 없음. HTTP API가 없는 정적 사이트이므로 코드와 메시지를 담은 에러 응답을 만들지 않는다. 잘못된 상태는 응답이 아니라 아래 세 자리에서 드러난다.

| 자리 | 시점 | 형태 |
| --- | --- | --- |
| 빌드 중단 | `astro build`, `astro dev` | 예외 메시지와 파일 경로를 표준 오류로 낸다 |
| 빌드 경고 | 마크다운 변환 | `console.warn` 한 줄. 빌드는 계속된다 |
| 화면 안내 | 브라우저 | 사용자가 읽을 한 문장. 코드 값을 노출하지 않는다 |

스크립트가 내는 메시지는 다음 형식을 따른다.

```
오류: <무엇이 잘못됐는지>. <무엇을 하면 되는지>
경고: <무엇을 건너뛰었는지> — <왜>
```

## 공통 코드 목록

상태 코드 체계를 쓰지 않으므로, 그 자리를 대신해 프로젝트 전체에 적용되는 실패 상황을 모아 둔다.

| 구분 | 메시지 | 발생 조건 | 결과 |
| --- | --- | --- | --- |
| 빌드 중단 | Zod 스키마 검증 실패. 파일 경로와 필드 이름을 알린다 | `title`, `date`, `summary` 누락 또는 타입 불일치 | 빌드가 멈춘다 |
| 빌드 중단 | `<id>의 related가 가리키는 글을 찾을 수 없다: <대상 id>` | `related`가 컬렉션에 없는 글을 가리킨다 | 빌드가 멈춘다 |
| 빌드 경고 | `[image-width] 폭으로 읽을 수 없는 값이라 무시한다: "<값>"` | 이미지 title이 `w=`로 시작하지만 값이 양의 정수가 아니다 | 이미지를 그대로 둔다 |
| 스크립트 오류 | `디렉터리가 아닙니다: <경로>` | `npm run images`에 잘못된 경로를 줬다 | 종료 코드 1 |
| 스크립트 오류 | `오류: <대상>가 이미 있어 덮어쓰지 않는다...` | 변환 결과와 같은 이름의 파일이 있다 | 그 파일만 건너뛰고 종료 코드 1 |
| 스크립트 경고 | `경고: 건너뜀 <파일> — <이유>` | 애니메이션 GIF이거나 이미 기준을 만족한다 | 종료 코드 0 |
| 스크립트 경고 | `경고: <파일>을 본문에서 참조하지 않는다` | 변환은 했으나 `index.md`에 참조가 없다 | 종료 코드 0 |
| 화면 안내 | `아직 발행한 글이 없습니다.` | 노출 대상 글이 0편이다 | 목록 대신 안내를 그린다 |
| 화면 안내 | `검색 결과가 없습니다.` | 검색 결과가 0편이다 | 목록을 감추고 안내를 보인다 |
| 조용한 실패 | 없음 | `localStorage` 읽기·쓰기가 막혔다 | 예외를 삼키고 기본 동작으로 이어 간다 |

## 도메인별 코드 규칙

코드 값을 쓰지 않으므로 접두 규칙 대신 메시지 작성 규칙을 정한다.

1. 빌드를 멈추는 메시지에는 언제나 어느 파일 또는 어느 글의 문제인지 식별자를 넣는다.
2. 경고는 무엇을 건너뛰었는지와 그 이유를 한 줄에 함께 적는다. 이유가 없는 경고는 남기지 않는다.
3. 사용자에게 보이는 안내에는 내부 식별자나 코드 값을 넣지 않는다.
4. 브라우저 저장소 접근처럼 실패해도 화면이 성립하는 자리는 알리지 않고 조용히 넘어간다.
5. 플러그인이 내는 메시지에는 `[<플러그인 이름>]` 접두를 붙여 어느 단계에서 났는지 드러낸다.

도메인 고유의 실패 조건은 각 도메인의 `03_API_명세.md`에 둔다.
